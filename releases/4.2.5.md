# AeroFTP 4.2.5

**26 October 2026.** This documentation accompanies AeroFTP 4.2.5. The [application changelog](https://github.com/axpdev-lab/aeroftp/blob/main/CHANGELOG.md) is the complete release record; [GitHub Releases](https://github.com/axpdev-lab/aeroftp/releases) provides the packages.

## Sync and Filename Safety

[AeroSync](/features/aerosync) keeps folder inventory, scan progress, Plan settings and Update mode across template export and import. Canonical Unicode names can correspond without losing their actual stored paths. Literal Unix backslashes remain part of a name, while ambiguous download names are rejected instead of overwriting another file.

Incomplete scans keep a partial result. AeroCloud does not infer that a remote file is absent just because a scan failed to see it. Compatible folder downloads begin transferring discovered files while the rest of the tree is still scanned.

## Proton Drive and Provider Operations

[Proton Drive](/providers/proton-drive) native mode reduces redundant metadata requests and overlaps blocks, files and folder scans. Its official CLI compatibility mode uses suitable native bulk groups for more transfers, including AeroSync and AeroCloud. The native and CLI modes have different paths and transfer behavior; see the guide before changing a profile's mode.

Filen Desktop's S3 preset waits for a fresh upload to become visible before a move or rename. OneDrive resolves shortcuts and shared folders across operations. WebDAV keeps real children whose names resemble the parent, and MEGAcmd profiles can resolve the path their local gateway actually serves.

## Windows Portable and Desktop Opening

[Windows portable builds](/getting-started/windows) keep logs in their portable data folder and preserve a dismissed isolation banner across startup and reboot. Preferences are reconciled after the credential vault becomes ready, and saving portable settings does not change an installed copy's startup entry.

Portable updates select the GUI executable correctly and retain a usable application path during replacement. Desktop Open with opens the selected file in AeroFile, with the appropriate image or text preview; files opened while the app starts are retained.

## CLI, MCP and AeroAgent

The [CLI reference](/cli/commands), [batch guide](/cli/batch-scripting), [MCP catalog](/mcp/overview) and [AeroAgent guide](/features/aeroagent) describe their respective command grammars, inventories and approvals. These are separate surfaces, even where they share a backend.

Hashsum can perform one checked full-download fallback when a server ignores ranges. MCP upload batches retain no-clobber and delay settings, and diagnostic and agent error messages redact complete Authorization values and quoted or escaped secret fields.

## Benchmark and Cleanup

The benchmark includes measured latency, signal bars and comparisons based on the protocols that actually supplied comparable samples. Ctrl+C and timeouts stop owned work, and the report distinguishes successful cleanup from cleanup the provider cannot perform.

On Nextcloud and ownCloud, benchmark and CLI speed-test cleanup can purge exactly the trash item created by the test. Koofr selective trash purge and Filen trash integration remain follow-ups. See the [benchmark reports](/test-reports/community-benchmark/) for methodology and dated measurements.

## Evidence and Limits

The update covers all 47 interface locales. Raw backend or provider error text may still be English. [Security documentation](/security/overview) describes the current storage and trust boundaries; historical [test reports](/test-reports/) keep their tested versions and dates and are not presented as new 4.2.5 measurements.
