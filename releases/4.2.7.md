# AeroFTP 4.2.7

This documentation accompanies AeroFTP 4.2.7, published on 8 November 2026. The [application changelog](https://github.com/axpdev-lab/aeroftp/blob/v4.2.7/CHANGELOG.md) is the complete release record. Packages are on the [GitHub release](https://github.com/axpdev-lab/aeroftp/releases/tag/v4.2.7). The previous notes stay at [4.2.6](/releases/4.2.6).

The figures below come from [`docs/PROVIDER-INVENTORY.json`](https://github.com/axpdev-lab/aeroftp/blob/v4.2.7/docs/PROVIDER-INVENTORY.json) at the `v4.2.7` tag. They are different counts, not a sum.

## Tigris and Fastly Object Storage

AeroFTP 4.2.7 adds two pre-configured S3 presets:

- **Tigris S3**: Static endpoints, region auto-detection, atomic metadata rename that protects moved objects, storage usage reporting with fallbacks, soft-deleted version handling in the trash, and bidirectional rclone import and export.
- **Fastly Object Storage**: 12 regional endpoints with path-style addressing, Fastly rclone bridge import and export, 16 MiB single-PUT cutoffs, 8 MiB multipart parts with bounded 408 and 429 retries, SigV4 7-day share link caps, 30-minute AeroCloud scan floors, and session-aware capability switching. See the [Fastly Object Storage setup guide](/providers/fastly-object-storage).

## Network trust, transfers and dialog stability

Network trust and destination validation are fail-closed: URL-parsed private, loopback and certificate checks protect connections, S3 keys with dot segments are rejected, and FTP passive connections pin to the control peer unless explicitly opted in.

Active transfers, synchronization, Apply operations and AI uploads stay bound to their initial server, profile, account and crypt scope across tab switches or connection handoffs. Unfinished cuts and unlinked targets retain their files safely.

Modal windows and comparison dialogs ignore accidental backdrop clicks, ensuring running transfers or comparisons are never inadvertently dismissed. Keyboard ESC prioritizes the topmost active decision prompt.

Credential vault writes acquire an exclusive cross-process lock across the GUI, CLI and MCP services with automatic cleanup of orphaned temporary files.
